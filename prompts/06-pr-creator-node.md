# PROMPT 06 — PRCreator node (branch → commit → push → Pull Request)

Read AGENTS.md. Load skill: github-pr-creator.

## Task
1. **`backend/tools/github_pr.py`** (use `requests` — already a dependency — for the GitHub REST API, and `_git_bin()` subprocess calls for git; no new heavy deps):
   - `parse_repo(url) -> (owner, name)`, `get_repo_info(owner, name)` (default branch, `permissions.push`).
   - `ensure_push_target(owner, name)`: if the token user has push rights → push to origin; else `POST /repos/{owner}/{name}/forks`, poll until the fork exists (≤ 30 s), push to the fork, and open the PR cross-repo (`head = "<forkowner>:<branch>"`).
   - `commit_and_push(work_dir, branch, message, files)`: `git -C work_dir checkout -b <branch>`, `git add <files>`, commit with `-c user.name="PatchForge Bot" -c user.email="patchforge-bot@users.noreply.github.com"`, push to `https://x-access-token:<token>@github.com/<owner>/<name>.git` (shallow clone push is OK because GitHub already has the base commit; if push fails with "shallow update not allowed", run `git fetch --unshallow` and retry once).
   - `open_pull_request(...)` → `POST /repos/{owner}/{name}/pulls`; add labels `security`, `patchforge` (ignore label errors).
   - Mask the token in ALL exception text and logs.
2. **PR body** — the template from the github-pr-creator skill (what was wrong / what changed / diff in `<details>` / proof table baseline → exploit-before ❌ → exploit-after ✅ / 0 regressions / reviewer checklist / agent trace with attempts + duration). Add a footer: "Generated by PatchForge (built on SentinelAI by Team Zen Hackers). Please review before merging."
3. **`backend/agents/remediation/pr_creator.py`** — `pr_creator_node(state)`: branch `patchforge/fix-<cwe-or-category>-<scan_id>`; commit only changed source files + exploit test; respect `DRY_RUN_PR=true` (write `PR.md` to artifacts, no push); set `pr_url`, `remediation_status="pr_opened"`. Logs: `[PRCreator] Branch patchforge/fix-cwe-89-ab12cd34 pushed`, `[PRCreator] 🎉 Pull request opened: <url>`.
4. **Report:** make `report_generator_node` include a `remediation` section `{status, target_vuln, attempts, diff, test_reports, review, pr_url}` (only when create_pr was true), so the frontend can render it from the final `done` message.
5. **Tests:** mock `requests` + subprocess: push-allowed path, fork path, token masking, DRY_RUN path.

## Acceptance
- With `DRY_RUN_PR=true`: full vulnbank run → `backend/runs/<id>/PR.md` exists; paste it.
- With a real token (fine-grained PAT: Contents RW + Pull requests RW on vulnbank): a real PR opens. Paste the URL.
- Run 3 times; report success rate and average duration; fix the root cause of any failure.
